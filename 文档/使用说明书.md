# ARAG 敏感信息识别系统 · 使用说明书

**版本**：v0.2.0　**协议**：MIT　**日期**：2026-09-12

---

## 1. 软件简介

ARAG 是一款**基于 RAG 的文档涉密信息检测系统**，核心逻辑是「先建库、后检测」：

1. **建库**：把按密级分类的敏感文档预处理、切片、向量化，建立敏感信息 RAG 库；
2. **检测**：对上传的待检文档 / 文本进行层级比对，输出各密级相似度，辅助判定是否含敏感 / 涉密内容。

典型使用场景：**文档外发审批、涉密程度定级评审**中的辅助决策。

三个密级：`0Public` 公开 · `1Restricted` 受限 · `2Confidential` 机密。

## 2. 环境要求与安装部署

### 2.1 环境要求

| 组件 | 要求 |
|------|------|
| Python | ≥ 3.9（后端 FastAPI + uvicorn） |
| Ollama | 需拉取嵌入模型 `bge-m3:latest`（1024 维，约 1.2 GB） |
| 可选 | `qwen3:14b`（LLM 摘要）、bge-reranker-v2-m3（重排序）、PaddleOCR / Tesseract（OCR） |
| 浏览器 | 现代浏览器（Chrome / Edge / Safari） |

### 2.2 目录约定（勿随意改动）

```
ARAG/
├── DOC/          # 源文档输入（按密级分 3 个子目录）
├── MD/           # 预处理产物（Markdown + 切片 JSON）
├── vector_db/    # ChromaDB 向量库（6 个集合）
├── DocScan/      # 待检文档暂存与中间产物
├── dedup_results/# 去重报告与删除备份
└── backend/ UI/ X2MD/ MD2RAG/   # 代码
```

### 2.3 启动与停止

```bash
./start.sh            # 一键启动全部（开发模式：前端 :3000 + 后端 :8000）
./start.sh front      # 仅前端
./start.sh back       # 仅后端
./start.sh status     # 查看服务状态
./start.sh stop       # 或 ./stop.sh：停止全部
```

- **开发模式**：访问 `http://localhost:3000`
- **部署模式**：若 `UI/build` 存在，后端单进程同源服务前端 + API，直接访问 `http://localhost:8000`（无需 nginx / Node）

### 2.4 API Key 认证（可选）

在 `.env` 中设置 `API_KEY` 即启用 API 认证中间件；留空（且 `AUTH_DISABLED=True`，仅限开发）则跳过认证。

## 3. 界面总览

顶部导航共 6 个页面，推荐使用顺序即导航顺序：

| 页面 | 功能 |
|------|------|
| 文件预处理 | ① 源文档转 Markdown + 父子块切片 |
| 数据入库 | ② 切片向量化写入 ChromaDB |
| 数据优化 | ③ 跨密级去重（可选） |
| 文档扫描 | ④ 上传待检文档做 DocScan 检测 / 文本即时扫描 |
| 数据库管理 | 查看各密级统计、重置数据库 |
| 系统设置 | 阈值、切片参数、上传限制、嵌入模型等 |

> 预处理 / 入库 / 去重 / 嵌入均为**后台任务**：页面可看到进度条、可取消，关闭浏览器不影响任务执行，重开页面会恢复进度轮询。

## 4. 知识库构建（一次性初始化工作）

### 4.1 准备源文档

把敏感资料按密级放入对应目录（支持 28 种扩展名：PDF / Word / Excel / PPT / 图片 / HTML / 纯文本等）：

```
DOC/0Public/          # 公开资料
DOC/1Restricted/      # 受限资料
DOC/2Confidential/    # 机密资料
```

### 4.2 文件预处理（X2MD）

1. 进入「文件预处理」页；
2. 选择处理范围（全部密级 / 单个密级）；
3. 按需调整：切片策略（父子块）、`chunk_size` / `chunk_overlap`、OCR（默认尽量少用，速度慢）、表格提取、LLM 摘要；
4. 点击启动任务，等待进度完成；失败的文件可单独**重试**。

产物写入 `MD/<密级>/`：`*.md` + `*.parents.json` + `*.children.json`。

### 4.3 数据入库（MD2RAG）

1. 进入「数据入库」页，启动入库任务；
2. 系统先做**去重预检**：已入库且内容未变的文档自动跳过（提示 `skipped`）；如需强制重建勾选 force；
3. 嵌入默认走 Ollama `bge-m3:latest`（每批 128 条，串行处理防超时）。

> ⏱️ 参考耗时：100 GB 文档一次性初始化约 **10-20 小时**（取决于硬件与是否启用 OCR）；万块级（~6000 切片）约 30 分钟（Apple M1 实测）。

### 4.4 数据优化（跨密级去重，可选但推荐）

1. 进入「数据优化」页启动去重比对任务（跨密级：受限×公开、机密×公开、机密×受限）；
2. 结果按相似度分三档报告（高 ≥0.8 / 中 0.65-0.8 / 弱 0.5-0.65），可人工审查；
3. 确认后「应用删除」：从**高密级**库删除与低密级重复的块（阈值默认 0.75，删除前自动备份 ID 清单到 `dedup_results/`）；
4. 也可开启 `auto_dedup` 自动执行——**不可逆操作，默认关闭**。

## 5. 文档检测 DocScan（核心功能）

「文档扫描」页含三个标签页：**文件扫描 · 文本扫描 · 文件管理**。文件检测四步：

### 5.1 上传待检文档
- 支持 `.pdf .docx .xlsx .pptx .txt .html .md` 共 7 种，大小上限 50 MB；
- 仅保存到 `DocScan/`，不自动处理；重名自动加后缀。

### 5.2 预处理 → 5.3 嵌入 → 5.4 层级比对
- 依次点击三个按钮（预处理 / 生成向量 / 层级比对）；嵌入为后台任务，可取消；
- **层级比对**（核心）：摘要 → 父块 → 子块逐级与三密级库比对，某级相似度 ≥ 80% 即跳过下级（整块标记高度相似），融合向量相似度 + 字面 n-gram + 连续匹配段 + 可选 reranker 打分。

### 5.5 结果解读

- 每个切片输出三密级相似度，形如 `/ARAG-end/public:0.85,restricted:0.72,confidential:0.91`；
- 高度相似显示 `SKIPPED:高度相似(public:0.92)`；
- 命中片段可**定位到原文位置**（bbox 高亮），相似度分档：
  - **≥ 0.8**：高度相似（几乎确定命中）
  - **0.65 – 0.8**：中度相似（需人工确认）
  - **0.5 – 0.65**：弱相关（仅供参考）

> 相似度为「adjusted」尺度：对 bge-m3 做了基线校正 `(raw − 0.37) / 0.63`，与原始余弦值不可混用。

## 6. 文本扫描（即时检测）

「文档扫描」→「文本扫描」标签页：直接粘贴文本（≥ 10 字符）→ 点击扫描 → 立即输出各密级相似度汇总与命中片段位置标注。适用于快速抽查段落、邮件、聊天记录等。

## 7. 系统设置

| 类别 | 可调项 |
|------|--------|
| 通用 | 相似度阈值、上传大小上限、日志等 |
| 切片 | `chunk_size` / `chunk_overlap` / 切片策略 |
| 嵌入 | 嵌入模型：`ollama-bge-m3`（默认）或 `mps-bge-m3`（Apple Silicon 本地推理） |
| OCR | 语言（`chi_sim+eng` / `chi_sim` / `eng`）、是否启用 |

⚠️ **切换嵌入模型会清空并重建向量库**（维度/语义空间不一致），属不可逆操作，切换后需重新入库。

设置持久化于 `runtime_settings.json`，重启后生效。

---

## 8. 数据库管理

- 查看各密级 parent / child 集合的块数统计；
- **重置数据库**：清空全部向量集合，不可逆，请确认已有备份。

备份提示：`vector_db/` 整体复制即备份；仓库保留 `vector_db_backup_*` 历史备份目录。

## 9. 常见问题（FAQ）

| 问题 | 处理 |
|------|------|
| 启动后页面打不开 | 检查后端日志 `backend.log`；确认 Ollama 已启动（`ollama list` 含 bge-m3:latest） |
| 入库报「维度不匹配」 | 曾切换嵌入模型——重置数据库后重新入库 |
| 入库中途内存高/被杀 | 系统已做恒定内存流式设计；若仍 OOM，逐密级入库并关闭图片入库 |
| 任务做到一半关页面 | 后台任务继续执行；重开页面自动恢复进度显示 |
| OCR 极慢 | 属正常（OCR 是兜底）；批量文档尽量用原生文本格式 |
| 去重想反悔 | `dedup_results/` 中保留删除 ID 备份 JSON；如做了整体备份可恢复 |
| 检测结果分数普遍偏高 | bge-m3 不相关文本基线约 0.37，展示分数已重标定；阈值可在系统设置调整 |
| 换机器/迁移 | 整目录复制；若嵌入模型版本不同，清库重新入库 |

## 10. 安全与数据说明

- **数据不出内网**：嵌入（Ollama）与向量库（ChromaDB）全部本地运行，无需外部 API；
- 上传文件名防路径穿越、扩展名白名单、大小限制；
- 去重删除、模型切换等破坏性操作均有备份或明确提示；
- 建议定期备份 `vector_db/` 与 `dedup_results/`。
