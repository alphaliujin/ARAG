# 切片时注入摘要的作用

## 什么是摘要注入

将文档的一句话摘要添加到每个切片的开头，例如：

```
原始切片：
"第三条 违约责任：甲方未按时支付款项，应承担每日千分之三的违约金。"

注入摘要后：
"【这是一个关于采购合同的违约条款】第三条 违约责任：甲方未按时支付款项，应承担每日千分之三的违约金。"
```

## 主要好处

### 1. 提高检索准确性（最重要）
- **问题**：单个切片可能缺少上下文，难以理解主题
- **解决**：摘要提供全文背景，帮助向量匹配更精准

**示例**：
- 搜索"合同违约"时
- 不带摘要的切片可能只匹配到"违约"二字
- 带摘要的切片明确包含"合同"+"违约"，匹配度更高

### 2. 提供上下文信息
- 切片单独看可能意义不明
- 摘要帮助理解这段内容属于什么主题

### 3. 增强语义表示
- 向量化时，摘要的高频词会提升整体权重
- 有助于跨段落的内容关联

### 4. 改善 RAG 效果
- LLM 生成答案时能快速了解文档背景
- 减少因缺少上下文导致的错误理解

## 代价

| 方面 | 影响 |
|-----|------|
| 处理时间 | 需要调用 LLM，每篇文档增加 1-10 秒 |
| 计算资源 | 消耗 Ollama/GPU 资源 |
| 成本 | 如果使用商业 API，会产生费用 |

## 建议

| 场景 | 建议 |
|-----|------|
| 追求检索质量 | ✅ 开启摘要注入 |
| 追求处理速度 | ❌ 关闭摘要注入 |
| 文档主题明确 | ❌ 可关闭（如都是合同） |
| 混合类型文档 | ✅ 建议开启（合同+简历+论文） |

## 当前配置

```ini
# x2md.conf
[chunk]
inject_abstract = false  # 默认关闭，提高处理速度
```

如需开启，修改为 `true` 并确保 LLM 服务可用。
